# Kalodata AI 内容雷达：优化后的任务流程

## 目标

为每个 TikTok Shop 美国站类目账号，持续发现**发布时间在最近 48 小时内、已挂商品、由 AI 生成、且仍有自然增长可能**的视频；经过次日复核后，才把其内容机制送入原创视频生产队列。

本流程复用的是内容机制，不复制原视频、原台词、人物、素材或镜头成片。

## 数据源职责

| 数据源 | 唯一职责 | 不承担的职责 |
|---|---|---|
| Kalodata `video/rank` | 发现 AI 视频：`is_ai_video=1` | 不能直接按发布时间筛选 |
| TikTok Video ID | 反推精确发布时间 | 不表示销量或增长 |
| Kalodata `video/detail` | 确认 AI 标记、挂商品数、播放、销量、收入、广告占比、时长 | 当前不返回可直接使用的商品链接 |
| FastMoss（补充） | 仅按已知 Video ID 补齐商品标题、链接、品类等 | 不作为 AI 视频发现源 |

## 每日 T0：候选发现与快照

### 榜单时效前提（已确认）

Kalodata 美国视频榜单按**美国自然日 T+1**更新：某美国日 `D` 的榜单数据，在美国日 `D+1` 的更新后才作为可读取数据出现。

因此本流程不把榜单当作实时流，而按数据日运行：

```text
美国日 D：视频发布、产生初始表现
美国日 D+1：Kalodata 更新 → 采集为 Snapshot_D（首次可见）
美国日 D+2：Kalodata 更新 → 同一 Video ID 采集为 Snapshot_D+1（次日复核）
```

定时复核固定在**北京时间 15:05**执行，以跨过 Kalodata 美国日 T+1 的更新边界；不在更新边界前拉取数据。

每次 15:05 运行必须按以下顺序完成两件独立工作：

1. **先复核上一轮 T0**：只读固定 Video ID，写入 T+1 对比结果；
2. **再扫描当日更新榜单**：`is_ai_video=1` + 发布时间反推 + 详情核验，建立新的 T0 池。

先后顺序不能颠倒，否则“最新 T0 文件”会被当作待复核对象，造成当天数据自比。

所有快照同时记录 `observed_at_utc`、美国本地日期和由 Video ID 反推的发布时间，避免把“榜单更新日”误写成“视频发布时间”。

### 1. 拉取 AI 视频榜

调用 Kalodata `tiktok/video/rank`：

```json
{
  "region": "US",
  "language": "en-US",
  "currency": "USD",
  "date_range": "lastDay",
  "page_number": 1,
  "page_size": 100,
  "is_ai_video": 1
}
```

- 连续读取多个页（初始为 10 页）。
- `date_range=lastDay` 是榜单指标统计窗口，**不是视频发布时间条件**。
- 不使用关键词搜索作为发现入口；账号类目通过 `category_ids` 限定，或在候选卡阶段按商品类目复核。

### 2. 用 Video ID 反推发布时间

TikTok Video ID 的高 32 位是 Unix 秒时间戳：

```text
published_at = UnixTime(video_id >> 32)
```

保留 `0 < 当前时间 - published_at <= 48 小时` 的记录。

将候选分层，避免把发布时间不足 24 小时的内容与完整 24 小时周期混为一谈：

| 层级 | 视频年龄 | 用途 |
|---|---:|---|
| 孵化观察 | 0–24 小时 | 记录，不做增长结论 |
| T0 候选 | 24–48 小时 | 可进入次日复核 |
| 过期发现 | 超过 48 小时 | 不进入本轮红利池 |

### 3. 详情核验与流量分层

对每个 24–48 小时候选调用 `tiktok/video/detail`，固定记录：

- `ai_video=1`
- `product_number >= 1`
- `views`、`sales_volumn`、`revenue`、`video_gpm`
- `digg_count`、`share_count`、`comment_count`
- `duration`
- `ad`、`ad_view_ratio`、`ad_revenue_ratio`

按广告情况分流，而不是混在一张榜里：

| 队列 | 条件 | 是否可直接作为复刻候选 |
|---|---|---|
| A：自然内容池 | `ad=0` | 是 |
| B：高效轻广告池 | `ad=1`、`ad_view_ratio ≤ 25`、`ads_roas ≥ 2.6` | 是，但标为“投放辅助红利”，与自然内容分开评估 |
| C：广告排除池 | 广告播放占比高 | 否；只保留诊断记录 |

`ads_roas` 由视频详情接口返回；榜单接口的 `ads_roas` 请求筛选当前实测不稳定，因此先用 `is_ai_video=1` 拉榜，再以详情返回值执行该二次筛选。25% 与 2.6 是当前业务规则，后续可用两周复核结果校准。

### 3.1 内容可复用性硬门槛

数据合格不等于值得复用。详情核验后、进入 T0 之前，增加人工或视觉模型的内容预审：

| 检查项 | 初始规则 | 处理 |
|---|---|---|
| 时长 | `duration <= 30 秒` | 超时直接排除，不进入本轮短视频复刻池 |
| 产品呈现 | 产品或结果必须在前 3 秒内可见 | 仅口播、长叙事或泛素材排除 |
| 可迁移机制 | 能清楚写出“钩子 → 演示/转变 → 卖点 → CTA” | 无明确机制、只依赖热梗或账号人设的内容排除 |
| 品牌/创作者依赖 | 不以特定品牌、明星、真人影响力或原账号关系为主要卖点 | 排除或仅归档观察 |
| 生成可行性 | 可用原创角色、场景、产品和台词完成 | 无法自然重做的动作、真人素材依赖内容排除 |

当前时长上限为便于首轮验证的 30 秒；未来根据账号实测完播和成交数据按类目调整，而非把长视频强行切成多个 10 秒片段。

### 4. 商品可承接校验

Kalodata 详情接口只证明“挂了商品”，不一定提供商品链接。因此对 A 池的已知 `video_id` 再做一次商品补齐：

1. 从 Kalodata 页面或 FastMoss 按 Video ID 获取商品标题、链接、品类、价格和佣金信息；
2. 排除医疗、减重、营养补充、治疗/修复宣称及其他功效型商品；
3. 确认目标账号可挂车、商品可售、库存和佣金正常；
4. 商品信息无法确认的候选保持“观察”，不能进入生产。

## T+1：固定 ID 次日复核

只读取 T0 已记录的 Video ID；不重新按排行榜找“新第一名”。

这里的 T+1 指 `Snapshot_D` 到 `Snapshot_D+1` 两次榜单更新之间的一个美国数据日，不是接口调用后的任意 24 小时。

### 复核方式

在与 T0 尽可能相同的时间调用同一详情接口，并使用同一 `date_range`。这得到的是两个相邻的 24 小时表现窗口，比较的是**增长速度**，不是视频全生命周期累计值。

记录：

```text
view_velocity       = T+1.views / T0.views
sales_velocity      = T+1.sales_volumn / T0.sales_volumn
revenue_velocity    = T+1.revenue / T0.revenue
gpm_change          = T+1.video_gpm - T0.video_gpm
ad_ratio_change     = T+1.ad_view_ratio - T0.ad_view_ratio
```

零值分母不计算比例，改为记录绝对增量和“数据不足”。

### 入选规则

候选进入“可拆解内容机制池”必须同时满足：

1. 仍是 `ai_video=1` 且 `product_number >= 1`；
2. T0 与 T+1 都没有转为重广告驱动；
3. 播放、成交或收入速度中至少两项未衰减，且至少一项增长；
4. 商品通过非功效、可挂车、可售校验；
5. 内容能够以原创人物、场景、文案、素材重新实现。

阈值不在首日写死。先用连续 14 天候选池计算各类目的自然增长分布，再按前 20% 的自然增长视频确定类目阈值。

## 生产前与生产后

```text
T+1 通过
  → 人工看原视频，写内容机制卡（钩子、冲突、演示、CTA）
  → 匹配可带货商品
  → 编写原创英文脚本和分镜
  → AI 视频生成、拼接、配音
  → 本地/飞书审核
  → 人工确认后发布
  → 回写发布后的播放、成交、佣金与违规结果
```

“脚本文字相似度超过 80%”不作为目标。保留的是卖点逻辑与节奏，文案、人物、场景、画面和镜头动作必须原创。
